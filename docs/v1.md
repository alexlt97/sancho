# Sancho Version 1

This document describes the current Version 1 implementation and the development workflow for Sancho. It is intentionally separate from the main README, which explains the project’s overall intention.

## V1 goal

Version 1 establishes a reliable offline chat foundation on a Pixel 9a running GrapheneOS. The app is terminal-first, uses Kotlin and Jetpack Compose, and keeps the local model behind a replaceable `LocalLlm` interface.

The V1 priority is dependable local chat before phone automation or unrestricted agent actions.

## Current capabilities

- User-selected `.litertlm` models are imported through Android’s document picker.
- Imported models are copied into the active GrapheneOS AI profile’s private app storage.
- LiteRT-LM provides local text inference through the CPU backend by default.
- Gemma image requests use the model’s native image-file input through the Photo Picker or camera flow.
- Assistant responses support common Markdown formatting, inline math such as `$5$`, and response-time display.
- The interface uses a dark galaxy theme, compact composer controls, image attachments, and camera input.
- A preview-only mock model streams deterministic responses without requiring a real model file.
- The app does not require network access, Google Play Services, or phone-action permissions for the V1 chat scope.

## Terminal workflow

```sh
make setup                 # provision the local JDK and Android toolchain
make check                 # compile, lint, tests, safety, and architecture checks
make build                 # create the debug APK
make test                  # run JVM tests
make instrumentation-build # compile Android instrumentation tests
make device                # list ADB devices
make install               # install to the authorized AI profile
make launch                # launch on the authorized AI profile
make e2e                   # run device or emulator UI tests
make benchmark             # measure CPU model load and generation
make gpu-benchmark         # measure the explicit GPU path
```

For the Pixel 9a, enable Developer options and USB debugging, accept the computer authorization prompt, and make sure the GrapheneOS profile named `AI` is active before running device commands.

## Visual preview

```sh
make preview
make preview-stop
```

The preview builds a mock-only variant and does not need a model import. It uses a resource-limited local emulator for UI iteration; it is not a GrapheneOS simulation and does not touch the Pixel 9a.

The normal `make build` and `make install` paths do not enable the mock runtime. Phone builds continue to use LiteRT-LM and require a real imported `.litertlm` model.

## Boundaries

The following remain outside the V1 milestone:

- unrestricted shell or phone-action execution from model output;
- background automation without explicit user confirmation;
- automatic model downloads;
- cloud inference as a required dependency;
- treating emulator verification as a substitute for Pixel/GrapheneOS verification.

The next agent-oriented work should introduce narrowly scoped tools, explicit schemas, and confirmation gates after the local chat loop is stable.
